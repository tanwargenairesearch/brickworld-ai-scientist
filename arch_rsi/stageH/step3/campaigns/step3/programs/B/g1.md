# Research program (generation 1)

## Goal
Find a policy network and training recipe that raise dev success at a fixed training budget. Change only what the task allows (network, recipe or both). The observation, reward and budget are fixed.

## Evidence from earlier searches (7 worlds, 84 trials)
- In 6 worlds, every trial scored exactly 0 on dev and in training, whatever the recipe (1-4 PPO epochs, 130k-430k steps, entropy 0.001-0.04, gamma 0.9-0.99) or the head (footprint pooling, per-layer heads, footprint convs, transformers, DONE tweaks). A uniform zero means the world deviates from its description. Recipe and capacity tweaks never moved a zero.
- The one success (world 2, about 0.22 under two recipes) was the layout-hedged reference net below. The same trunk without the hedge, on the same recipe, scored 0. It was found in the last round and never refined.
- Layout-free heads that learn slowly never escaped zero: zero-initialised dense remaps, flat MLPs, per-action attention.
- Heads that hard-code footprints, top-left anchors or obs channel meanings fail silently when the world deviates.

## Reference net (world 2)
Inputs:
- the obs;
- the mask's placement part reshaped to (n_types, Y, X) under four layouts: as is; read as (T, X, Y) then transposed; y-flipped; x-flipped;
- 2 coordinate channels.

Body: 1x1 conv to 64, then 1x1 conv to 40, then two residual 3x3 convs of width 40.

Head: relu(3x3 conv to 32 + 1x1 skip), then four 1x1 convs, each to n_types maps. Re-lay map k by its layout (as is, transpose, y-flip, x-flip), flatten, and sum the four into the placement logits.

DONE and value: Linear on the mean and max of the trunk features to 64, ReLU, then Linear. Compute r is about 1.

Recipe: lr 2e-3, n_envs 128, rollout_len 16, n_minibatches 8, ppo_epochs 2, ent_coef 0.002, gamma 0.9, gae_lambda 0.85.

## How to run each round
1. Read every result, including training success. Any nonzero training success is the signal to follow. If everything is 0, the deviation is still unfound: change what the network assumes, not the recipe.
2. Before proposing, write down which deviations the results so far rule out.
3. Round 1 should include:
   - the reference net, unchanged;
   - a wider hedge: all 8 grid symmetries times type-major and type-minor action order, on both the mask inputs and the output maps;
   - a version with a 5x5 head conv, to hedge footprints and anchors;
   - bets on other deviations: the DONE index, the obs channel order, the obs transposed relative to the mask.

   While all scores are 0, propose no recipe-only or capacity-only candidates.
4. Once something scores above 0, about half the candidates refine it with one change each: keep only the layout components that matter; widen or deepen the trunk; try 1 PPO epoch for more samples; vary lr, entropy and horizon. The rest test new ideas. With one seed, differences under about 0.07 may be noise.
5. If two rounds stay at 0, hedge more radically:
   - different dynamics (no drop, other heights);
   - an action count or grid size other than described;
   - permuted obs channels.

   The mask is the one input known to share the action layout, so let the network read heights and legality from it. Check that n_place equals n_types*Y*X before reshaping; otherwise embed the mask with a Linear layer.
6. Give every candidate a hypothesis: what changes, which deviation or bottleneck it targets, and what result would refute it.
7. Keep files simple and correct:
   - Use spec fields (Y, X, Z, n_types, n_place), never fixed sizes, since grid sizes vary.
   - Stay near r=1: cheaper nets are charged r=1 anyway, and 3D convs are slow.
   - Start hedged components at full scale and sum them, so each gets gradient at once. Never put them behind zero-initialised or softmax gates.
8. Do not repeat a refuted idea unless you say what differs this time.

## Revising this program
After each generation of searches, you rewrite this program from their logs. It is then used in new worlds, including grid sizes you will not see.
- Keep advice the evidence supports, and cite that evidence.
- Drop advice that did not help.
- Write lessons that hold across grid sizes.
- Stay under 1,000 words, including this section.

## How the program is used
The header (the HTML comment) is read only by the search code. Bounds: rounds 2-6, candidates_per_round 2-6, seeds_per_candidate 1-3, and their product at most 24. Keep its format. The selected trial is retrained on 4 new seeds, and that is the score.

The rest of the program is given to every round, together with the task description, interface rules, starting architecture, results so far and budget. Searches see only scores: dev success per seed, training success, parameters, compute, steps and time.

Policies and features must be learned. Never advise hand-written placement rules or scores, hand-computed features before a learned layer, hand-set weights, or ways to pass the checks without learning.
