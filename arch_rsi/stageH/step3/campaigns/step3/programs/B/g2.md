# Research program (generation 2)

## Goal
Raise dev success at the fixed training budget by changing the network, the recipe or both. Observation, reward and budget are fixed.

## Evidence from 14 searches
- Most worlds deviate from their description, and the starting net scores 0. Changing only the recipe or capacity never moved a zero.
- The usual deviation is a frame mismatch between the obs and the action/mask layout. Found so far: actions transposed (world 2), x-flipped (6) or y-flipped (7); obs reoriented relative to the actions (1, 5), fixed by feeding the obs under all 8 grid symmetries.
- Hedges work in sets of about 4. Four summed layouts scored 0.15-0.25 in 4 worlds. Sums of 16 or 24 layouts scored 0 in nearly every try.
- Splitting decided searches. Once a 4-layout hedge scored, the single correct layout scored 0.80-0.94 and each wrong one exactly 0 (worlds 1, 2, 6, 7). Searches that never split fully (3, 4, 5) ended at 0.2-0.44.
- In world 4, only per-cell LayerNorm on separate obs and mask stems, with output layers initialised at gain 0.01, escaped zero (0.15-0.21). This suggests inputs on an unexpected scale.
- On aligned nets these hurt: 1 PPO epoch (0.40, 0.08, 0.31 against 0.8-0.9), a third residual block or a wider trunk (fewer samples), a 5x5 head, gamma ≥0.97, and n_envs 64 (collapsed in 2 worlds). Gains within noise: ent_coef 0.005-0.01, 16 minibatches, lr 3e-3, 3 epochs, gamma 0.95.
- Single-seed results are bimodal: a lone 0 after a minor tweak may be a bad seed.

## Reference net
Inputs: the obs; the mask's placement part reshaped to (K, Y, X), with K = n_place/(Y·X), under each layout of a set; 2 coordinate channels.
Body: 1x1 conv to 64, 1x1 conv to 40, two residual 3x3 convs of width 40.
Head: relu(3x3 conv to 32 + 1x1 skip), then a 1x1 conv to K maps per layout. Re-lay each map by its layout, flatten, and sum into the placement logits.
DONE and value: Linear on the mean and max of the trunk features to 64, ReLU, then one Linear each. r≈1.
A layout is the (K, Y, X) reading, optionally transposed, then y-flipped, then x-flipped. Sets:
- A = {identity, transpose, y-flip, x-flip};
- B = {y+x-flip, transpose+y-flip, transpose+x-flip, transpose+y+x-flip}.

Recipe: lr 2e-3, n_envs 128, rollout_len 16, n_minibatches 8, ppo_epochs 2, ent_coef 0.005, gamma 0.9, gae_lambda 0.85.

## How to run each round
1. Read every result, including training success. Any nonzero score is the signal. Write down which deviations the results rule out.
2. Round 1, all on the reference recipe:
   - set A; set B;
   - set A, and set B, each with the obs under 8 grid symmetries (4 flips if Y≠X) fed into the stem;
   - set A with LayerNorm stems and trunk, and gain-0.01 outputs;
   - set A with obs symmetries and LayerNorm.
3. Round 2: split. Run all 4 single layouts of the best-scoring set, keeping its other components. Use spare slots to split a scoring net's other hedges (for example single obs views), or to remove one component and see whether it is needed. Never test only one single layout: in world 5 the identity layout alone scored 0.08 and the other three were never tried.
4. Rounds 3-4: refine the best single-layout net with one change each: ent_coef 0.01, n_minibatches 16, lr 3e-3, 3 PPO epochs, gamma 0.95, or a Linear of the pooled global features added into every head cell. Then combine the best two or three. Avoid the changes listed as harmful.
5. If round 1 is all 0, combine a few hedges rather than widening the layouts: obs symmetries + LayerNorm + global context in each residual block + a dilated block, with set A or B. Also try type-minor (K innermost) versions of A and B. In world 3 only such a combination escaped. If still 0, try a separate critic with gamma 0.99 and ent_coef 0.01.
6. Give every candidate a hypothesis: what changes, which deviation or bottleneck it targets, and what result would refute it. With one seed, gaps under about 0.1 are noise.
7. Files:
   - Use spec fields (Y, X, n_place, n_actions), never fixed sizes. If n_place ≠ K·Y·X, embed the mask with a Linear layer. Transposes need Y = X.
   - Sum hedged components at full scale. No zero-initialised or softmax gates.
   - Keep RECIPE and other constants as literals. Keep r under about 1.6, because very costly nets failed the check that the budget allows at least 4 updates.
8. Do not repeat a refuted idea unless you say what differs this time.

## Revising this program
After each generation, rewrite this program from the search logs. It is then used in new worlds, including grid sizes not seen before. Keep advice the evidence supports and cite it. Drop advice that did not help. Write lessons that hold across grid sizes. Stay under 1,000 words.

## How the program is used
The header is read only by the search code. Bounds: rounds 2-6, candidates_per_round 2-6, seeds_per_candidate 1-3, product at most 24. Keep its format. The selected trial is retrained on 4 new seeds, and that is the score. The rest of the program is given to every round, with the task description, interface rules, starting architecture, results so far and budget. Searches see only scores. Policies and features must be learned. Never advise hand-written placement rules, hand-computed features before a learned layer, hand-set weights, or ways to pass the checks without learning.
